The prose spec is normative for humans; these artifacts are normative for machines.

## JSON Schemas

Control-plane payloads are locked by JSON Schema (draft 2020-12) in [`schemas/`](https://github.com/ashreo/Mixum-Agent-Protocol/tree/main/schemas):

| Schema | Locks |
|---|---|
| `envelope.schema.json` | The control envelope (`v`, `id`, `op`, `seq`, `replyTo`, `ts`, `payload`) |
| `token.schema.json` | `map1.` token claims (`sub`, `caps`, `iat`, `exp`, `jti`, `taskId`, `windows`, `mem`) |
| `task.schema.json` | Task object and `task.event` |
| `snapshot-node.schema.json` | SnapNode (tree node) |
| `snapshot-manifest.schema.json` | Snapshot manifest (`files`, `dirs`, chunks) |
| `memory-record.schema.json` | Memory record (MAP-Memory) |
| `bridge-message.schema.json` | MAP-Bridge messages (runner ↔ agent) |
| `privilege.schema.json` | Privilege request/decision/list reply and the audit record (Experimental) |

Binary layouts (video frame header, chunk records, stdio records) are byte-exact in the spec chapters and intentionally **not** expressible as JSON Schema — the vectors below lock them.

## Conformance vectors

Structural vectors live in [`vectors/`](https://github.com/ashreo/Mixum-Agent-Protocol/tree/main/vectors) and are language-neutral: a conformant implementation must accept every `valid` case and reject every `invalid` case with the stated error code.

| Vector set | Scope |
|---|---|
| `vectors/envelope/` | Envelope validation, reply conventions, error-code usage |
| `vectors/snapshot-tree/` | Tree semantics: restore-inplace parallel timeline, fork numbering, leaf-only delete |
| `vectors/bridge-session/` | A full MAP-Bridge session transcript (hello → exec → input → done) |
| `vectors/privilege/` | Approval/deny/timeout/expiry flow, executable pinning, audit records |
| `vectors/tokens/` | *(planned post-skeleton)* signed `map1.` token pairs generated by the Rust SDK |

Crypto vectors (token signatures, chunk hashing) are generated by a reference implementation and pinned; they land with the first SDK release rather than hand-written.

## Using them

- **SDK CI**: validate every codec round-trip against the schemas.
- **Node CI**: run the vectors; print the profile list you pass.
- **Fuzzing**: schemas double as generators — unknown-field tolerance is itself a conformance rule.
